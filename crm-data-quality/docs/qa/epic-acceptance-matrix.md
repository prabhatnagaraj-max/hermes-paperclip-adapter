## Purpose

Define explicit, testable acceptance criteria for each CRM-DQ child epic and map each criterion to concrete verification evidence. `Mandatory` criteria are required for epic closure. `Stretch` criteria improve confidence/readiness but are not strict closure gates.

## Review Notes for FoundingEngineer

- Current source docs use both `test/*` and historical `tests/*` acceptance artifact references. This matrix uses existing paths in this repo (`test/cases/*`, `test/PLAN.md`, `docs/qa/epic-acceptance-matrix.md`) and calls out planned live-env docs separately.
- Epic 4 has a concrete pre-env CI workflow at `.github/workflows/crm-dq-ci.yml`; closure should attach an actual workflow run when one is available, not only the static YAML.
- Epic 5 references `docs/release-readiness-checklist.md` as a planned stretch artifact because it is not present in this checkout. FoundingEngineer should confirm whether that remains in scope for VER-321 or belongs to a later readiness gate.
- Epic 6 rows are intentionally env-dependent. They should not close from placeholder docs; FoundingEngineer owns tenant/auth/data prerequisites before those criteria can pass.
- Eng-6 remains listed as a scope gap in `docs/environment-dependency-map.md`; FoundingEngineer should decide whether to create a dedicated Eng-6 issue before Epic 6 starts.
